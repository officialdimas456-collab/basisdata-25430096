## 1. PENDAHULUAN & PRINSIP PENGUJIAN

Dokumen ini menyajikan rencana serta hasil eksekusi pengujian manipulasi data (*Data Manipulation Language / DML*) pada basis data `akad_096`. Pengujian ini dilakukan untuk memastikan bahwa seluruh aturan bisnis (*Business Rules*) dan penegakan integritas data yang dikonfigurasikan pada DDL Modul 5 berjalan dengan akurat di lingkungan MariaDB.

### 1.1 Kategori Pengujian
1. **Uji Positif (Positive Testing):** Memastikan data yang sah/valid dapat diterima dan disimpan oleh server MariaDB tanpa hambatan.
2. **Uji Negatif (Negative Testing):** Memastikan data yang tidak valid atau melanggar batasan integritas (*Primary Key*, *Foreign Key*, *Unique*, *Check*) ditolak secara otomatis oleh server dengan menghasilkan kode galat (*error code*) yang sesuai.

### 1.2 Urutan Ketergantungan Pengisian Data (Data Dependency)
Pengisian data sampel dilakukan secara bertahap dari tabel induk (*master*) hingga tabel anak (*transactional*):
$$\text{Dosen / Mata Kuliah / Ruang / Mahasiswa} \longrightarrow \text{Jadwal Kuliah} \longrightarrow \text{KRS} \longrightarrow \text{KRS Detail} \longrightarrow \text{Nilai}$$

### 2.3 Operasi Pembaruan (UPDATE) dan Penghapusan (DELETE) Aman

```sql
-- Aktivasi Mode Aman (Safe Update Mode)
SET SESSION sql_safe_updates = 1;

-- -------------------------------------------------------------
-- A. OPERASI UPDATE AMAN (Menggunakan Key Column)
-- -------------------------------------------------------------

-- 1. Mengubah status mahasiswa berdasarkan Primary Key
UPDATE mahasiswa 
SET status_mahasiswa = 'aktif', no_hp = '081299998888' 
WHERE id_mahasiswa = 5;

-- 2. Mengubah kapasitas ruang kuliah berdasarkan Unique Key / PK
UPDATE ruang_kuliah 
SET kapasitas = 45 
WHERE id_ruang = 1;

-- -------------------------------------------------------------
-- B. OPERASI DELETE AMAN (Menggunakan Primary Key)
-- -------------------------------------------------------------

-- 1. Menghapus data draf nilai yang salah berdasarkan PK
DELETE FROM nilai 
WHERE id_nilai = 35;

-- 2. Menghapus data rincian KRS berdasarkan PK
DELETE FROM krs_detail 
WHERE id_krs_detail = 70;
```

## 4. VERIFIKASI REKAPITULASI DATA SAMPEL

Untuk membuktikan kecukupan kuota minimum data sampel transaksi ($10 \times P = 70$), kueri rekapitulasi berikut dijalankan pada server:

```sql
SELECT 'dosen' AS nama_tabel, COUNT(*) AS jumlah FROM dosen
UNION ALL SELECT 'mata_kuliah', COUNT(*) FROM mata_kuliah
UNION ALL SELECT 'ruang_kuliah', COUNT(*) FROM ruang_kuliah
UNION ALL SELECT 'mahasiswa', COUNT(*) FROM mahasiswa
UNION ALL SELECT 'jadwal_kuliah', COUNT(*) FROM jadwal_kuliah
UNION ALL SELECT 'krs', COUNT(*) FROM krs
UNION ALL SELECT 'krs_detail', COUNT(*) FROM krs_detail
UNION ALL SELECT 'nilai', COUNT(*) FROM nilai;
```

```text
| jadwal_kuliah  |      5 |

```
