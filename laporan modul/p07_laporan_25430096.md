## 2.2 Urutan Evaluasi SELECT

Walaupun perintah SQL ditulis dengan urutan `SELECT`, `FROM`, `WHERE`, `ORDER BY`, dan `LIMIT`, proses evaluasinya secara logis memiliki urutan berbeda:

1. `FROM`: menentukan tabel sumber data.
2. `WHERE`: menyaring baris sesuai kondisi.
3. `SELECT`: menentukan kolom dan ekspresi yang ditampilkan.
4. `ORDER BY`: mengurutkan hasil.
5. `LIMIT`: membatasi jumlah hasil.

Hal ini menjelaskan mengapa alias yang dibuat pada bagian `SELECT` belum dapat digunakan secara langsung pada `WHERE`.

## 3.2 D.2 Pola Teks dan Nilai Kosong

### Langkah 3. Menampilkan data mahasiswa dengan format yang mudah dibaca

Pada langkah ini digunakan beberapa fungsi skalar untuk mengolah teks, tanggal, nilai kosong, dan kondisi status keaktifan mahasiswa.

```sql
SELECT
    CONCAT(nama_mahasiswa, ' (', nim, ')') AS mahasiswa_info,
    DATE_FORMAT(NOW(), '%d-%m-%Y') AS tanggal_akses,
    IFNULL(no_hp, 'Tidak Ada Kontak') AS kontak_hp,
    CASE status_mahasiswa
        WHEN 'aktif' THEN 'Status: Aktif Studi'
        ELSE 'Status: Nonaktif / Cuti'
    END AS keterangan_status
FROM mahasiswa
WHERE nama_mahasiswa LIKE '%a%'
ORDER BY nama_mahasiswa ASC
LIMIT 5;
```

**Penjelasan fungsi:**

- `CONCAT()` menggabungkan nama mahasiswa dengan NIM.
- `DATE_FORMAT()` menampilkan format tanggal pengaksesan data.
- `IFNULL()` mengganti nilai kontak yang bernilai `NULL` dengan teks penjelas.
- `CASE` memberikan keterangan status keaktifan studi mahasiswa.
- `LIKE '%a%'` mencari nama mahasiswa yang mengandung huruf 'a'.
- `ORDER BY ... ASC` mengurutkan nama mahasiswa secara alfabetis (A-Z).
- `LIMIT 5` membatasi hasil menjadi maksimal lima baris.

**Hasil:** Data mahasiswa yang namanya mengandung huruf 'a' ditampilkan dalam format rapi berkapasitas 5 baris.

# 4. Jawaban Titik Analisis

## 4.1 Titik Analisis 1: Penggunaan Alias pada WHERE

**Pertanyaan:** Mengapa ketika `ORDER BY simulasi_beban` diganti menjadi `WHERE simulasi_beban > 3`, muncul galat? Bagaimana menulis kondisi yang setara tanpa menggunakan alias?

**Jawaban:**

Galat muncul karena alias `simulasi_beban` dibuat pada bagian `SELECT`, sedangkan klausul `WHERE` dievaluasi lebih dahulu oleh MariaDB. Saat proses filtering `WHERE` berlangsung, alias dari bagian `SELECT` belum terbentuk.

Kueri yang menghasilkan galat:
```sql
SELECT sks + 1 AS simulasi_beban
FROM mata_kuliah
WHERE simulasi_beban > 3;
```

Perbaikannya adalah menuliskan kembali ekspresi perhitungannya secara langsung pada `WHERE`:
```sql
SELECT sks + 1 AS simulasi_beban
FROM mata_kuliah
WHERE sks + 1 > 3;
```

**Kesimpulan:** Alias dapat digunakan pada bagian `ORDER BY`, tetapi **tidak dapat** digunakan pada `WHERE` dalam kueri yang sama karena urutan evaluasi logika SQL (`FROM` $\rightarrow$ `WHERE` $\rightarrow$ `SELECT` $\rightarrow$ `ORDER BY`).

---

## 4.2 Titik Analisis 2: Perbedaan NULL dan String Kosong

**Pertanyaan:** Mengapa `WHERE no_hp = NULL` tidak pernah mengembalikan baris, padahal terdapat mahasiswa yang belum mengisi nomor HP?

**Jawaban:**

`NULL` mewakili kondisi *unknown* (nilai tidak ada/belum diisi). Dalam standar SQL, nilai `NULL` tidak bisa diperiksa dengan operator perbandingan konvensional seperti sama dengan (`=`). Operasi `= NULL` akan selalu menghasilkan `UNKNOWN` (dianggap false).

Kueri yang salah:
```sql
SELECT * FROM mahasiswa WHERE no_hp = NULL;
```

Kueri yang benar:
```sql
SELECT * FROM mahasiswa WHERE no_hp IS NULL;
```

Perbedaan `NULL` dengan string kosong (`''`):

| `NULL` | String Kosong (`''`) |
|---|---|
| Tidak memiliki nilai / data tidak diketahui. | Memiliki nilai berupa karakter teks dengan panjang nol. |
| Diperiksa menggunakan `IS NULL`. | Diperiksa menggunakan `= ''`. |
| Tidak memakan ruang penyimpanan string. | Merupakan nilai string yang sah. |

## 4.3 Titik Analisis 3: Perhitungan Subtotal dan IPK/IPS (Fungsi Agregat)

**Pertanyaan:** Skor perkalian per baris mata kuliah dapat dihitung pada Modul 7, tetapi total Indeks Prestasi (IPS) belum. Mengapa? Fitur SQL apa yang dibutuhkan?

**Jawaban:**

Pada Modul 7, kalkulasi matematika hanya dapat dilakukan secara *row-by-row* (per baris individual). Untuk menghitung nilai IPK/IPS, kita perlu mengagregasi seluruh baris nilai dalam satu KRS, menjumlahkan total perkalian bobot, dan membaginya dengan total SKS.

Guna melakukan hal ini, diperlukan fungsi agregat `SUM()` dan klausul `GROUP BY`.

Contoh konsep kueri yang akan datang:
```sql
SELECT no_krs,
       SUM(nilai_angka * bobot_nilai) / SUM(bobot_nilai) AS ips
FROM nilai_khs
GROUP BY no_krs;
```

**Kesimpulan:** Perhitungan skalar bekerja per baris data, sedangkan penghitungan kumulatif (seperti total nota atau IPK) memerlukan fungsi agregat (`SUM()`, `AVG()`) dan `GROUP BY` yang dipelajari pada modul berikutnya.

## 5.2 Latihan 2: Kesalahan Semantik dan Perbaikannya (Operator Logika AND/OR)

**Pertanyaan:** Bagaimana menampilkan mata kuliah pada Semester 3 yang SKS-nya $\ge 3$ atau nama mata kuliahnya mengandung kata 'Basis'?

### Kueri yang salah secara semantik
```sql
SELECT *
FROM mata_kuliah
WHERE semester_kurikulum = 'Semester 3'
  AND sks >= 3
   OR nama_mk LIKE '%Basis%';
```

**Mengapa salah?**
Operator `AND` memiliki prioritas presedensi lebih tinggi daripada `OR`. MariaDB akan mengevaluasi `(semester_kurikulum = 'Semester 3' AND sks >= 3)` terlebih dahulu. Akibatnya, seluruh mata kuliah dari semester berapapun yang mengandung kata 'Basis' akan ikut ditampilkan.

### Kueri yang sudah diperbaiki
```sql
SELECT *
FROM mata_kuliah
WHERE semester_kurikulum = 'Semester 3'
  AND (
      sks >= 3
      OR nama_mk LIKE '%Basis%'
  );
```

**Penjelasan perbaikan:** Tanda kurung `()` memaksa MariaDB mengevaluasi kondisi di dalamnya terlebih dahulu sebelum mengombinasikannya dengan filter `semester_kurikulum = 'Semester 3'`.

# 7. Pembahasan dan Kendala

Selama praktikum Modul 7, diketahui bahwa penggunaan perintah `SELECT` berfungsi penting untuk menyajikan data secara kontekstual. Operator `LIKE`, `BETWEEN`, `IN`, dan `IS NULL` mempermudah penyaringan data, sementara fungsi skalar (`CONCAT`, `UPPER`, `DATE_FORMAT`, `IFNULL`, `CASE`) membuat hasil tampilan menjadi lebih informatif.

**Kendala yang dihadapi & penyelesaiannya:**
1. **Alias pada `WHERE`:** Penggunaan alias kolom pada `WHERE` memicu galat. Solusinya adalah menulis ulang rumus aritmatika di dalam klausul `WHERE`.
2. **Kondisi `NULL`:** Pencarian kolom kosong gagal saat menggunakan `= NULL`. Solusinya adalah beralih menggunakan operator `IS NULL`.
3. **Presedensi Operator Logika:** Operator `AND` dan `OR` tanpa tanda kurung menghasilkan baris data yang keliru secara semantik. Solusinya adalah menambahkan tanda kurung `()` pada kondisi pengelompokan.
4. **Keterbatasan Kueri 1 Tabel:** Beberapa kebutuhan informasi proyek `akad_096` belum bisa dijawab utuh karena membutuhkan relasi antartabel (`JOIN`) dan perhitungan agregat (`GROUP BY`).
