## 1. Tujuan Praktikum

- Mampu merancang dan menuliskan skrip *Data Definition Language* (DDL) untuk membuat basis data dan tabel relasional.
- Mampu menerapkan berbagai jenis *constraint* seperti `PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, `NOT NULL`, dan `CHECK` guna menjaga integritas data.
- Memahami pengaruh klausa referensial seperti `ON DELETE CASCADE` dan `ON DELETE SET NULL` pada tabel transaksi.

---

## 2. Ringkasan Dasar Teori

- **DDL (Data Definition Language):** Perintah SQL yang digunakan untuk mendefinisikan struktur basis data, meliputi perintah `CREATE`, `ALTER`, dan `DROP`.
- **Constraint (Batasan):** Aturan yang diterapkan pada kolom atau tabel untuk memvalidasi data yang masuk demi menjamin keabsahan, konsistensi, dan keutuhan relasi antarentitas.
- **Integritas Referensial:** Mekanisme yang memastikan hubungan antartabel melalui *Foreign Key* tetap sinkron dan mencegah munculnya data yatim (*orphan data*).

## 3. Hasil Langkah Percobaan

### A. Skrip Pembuatan Database dan Tabel Induk (`db_akademik_096`)

```sql
CREATE DATABASE IF NOT EXISTS db_akademik_096;
USE db_akademik_096;

DROP TABLE IF EXISTS detail_krs;
DROP TABLE IF EXISTS krs;
DROP TABLE IF EXISTS mahasiswa;
DROP TABLE IF EXISTS mata_kuliah;
DROP TABLE IF EXISTS dosen;

CREATE TABLE dosen (
    id_dosen SMALLINT NOT NULL AUTO_INCREMENT,
    kode_dosen CHAR(3) NOT NULL,
    nidn CHAR(10) NOT NULL,
    nama_dosen VARCHAR(100) NOT NULL,
    prodi_dosen VARCHAR(60) NOT NULL,
    PRIMARY KEY (id_dosen),
    UNIQUE KEY uq_dosen_kode (kode_dosen),
    UNIQUE KEY uq_dosen_nidn (nidn)
) ENGINE=InnoDB;

CREATE TABLE mata_kuliah (
    id_mk INT NOT NULL AUTO_INCREMENT,
    kode_mk VARCHAR(10) NOT NULL,
    nama_mk VARCHAR(100) NOT NULL,
    sks_mk INT NOT NULL DEFAULT 3,
    semester_penawaran TINYINT NOT NULL DEFAULT 1,
    PRIMARY KEY (id_mk),
    UNIQUE KEY uq_mk_kode (kode_mk),
    CONSTRAINT ck_mk_sks
        CHECK (sks_mk > 0 AND sks_mk <= 6)
) ENGINE=InnoDB;

CREATE TABLE mahasiswa (
    id_mahasiswa INT NOT NULL AUTO_INCREMENT,
    nim CHAR(8) NOT NULL,
    nama_mhs VARCHAR(100) NOT NULL,
    prodi_mhs VARCHAR(60) NOT NULL,
    no_hp_mhs VARCHAR(15) NULL,
    status_mhs ENUM('aktif', 'cuti', 'nonaktif')
        NOT NULL DEFAULT 'aktif',
    tgl_daftar_mhs DATE NOT NULL,
    id_dosen_pa SMALLINT NULL,
    PRIMARY KEY (id_mahasiswa),
    UNIQUE KEY uq_mhs_nim (nim),
    CONSTRAINT fk_mhs_dosen_pa
        FOREIGN KEY (id_dosen_pa)
        REFERENCES dosen (id_dosen)
        ON DELETE SET NULL
) ENGINE=InnoDB;
```

### B. Skrip Pembuatan Tabel Transaksi

```sql
CREATE TABLE krs (
    id_krs INT NOT NULL AUTO_INCREMENT,
    no_krs CHAR(12) NOT NULL,
    tgl_pengisian DATETIME NOT NULL,
    semester_akademik CHAR(5) NOT NULL,
    id_mahasiswa INT NOT NULL,
    PRIMARY KEY (id_krs),
    UNIQUE KEY uq_krs_no (no_krs),
    CONSTRAINT fk_krs_mahasiswa
        FOREIGN KEY (id_mahasiswa)
        REFERENCES mahasiswa (id_mahasiswa)
) ENGINE=InnoDB;

CREATE TABLE detail_krs (
    id_krs INT NOT NULL,
    id_mk INT NOT NULL,
    nilai_huruf CHAR(2) NULL,
    nilai_angka DECIMAL(3,2) NULL,
    PRIMARY KEY (id_krs, id_mk),
    CONSTRAINT fk_detail_krs
        FOREIGN KEY (id_krs)
        REFERENCES krs (id_krs)
        ON DELETE CASCADE,
    CONSTRAINT fk_detail_mk
        FOREIGN KEY (id_mk)
        REFERENCES mata_kuliah (id_mk),
    CONSTRAINT ck_detail_nilai_angka
        CHECK (nilai_angka >= 0.00 AND nilai_angka <= 4.00)
) ENGINE=InnoDB;
```

## 4. Jawaban Titik Analisis

### Perbedaan ON DELETE CASCADE dan RESTRICT

**Pertanyaan:** Mengapa `fk_detail_krs` menggunakan `ON DELETE CASCADE`, sedangkan `fk_detail_mk` tidak? Apa yang terjadi pada riwayat akademis atau transkrip jika mata kuliah boleh dihapus beserta seluruh detailnya?

**Jawaban:**

**Alasan `fk_detail_krs` menggunakan `ON DELETE CASCADE`:**

Tabel `detail_krs` merupakan rincian transaksi yang bergantung pada tabel `krs`. Apabila data KRS dihapus, seluruh detail di dalamnya ikut terhapus secara otomatis. Hal ini mencegah munculnya data yatim (*orphan data*).

**Alasan `fk_detail_mk` tidak menggunakan `ON DELETE CASCADE`:**

Tabel `mata_kuliah` merupakan entitas referensi master. Mata kuliah yang pernah diambil mahasiswa tidak boleh dihapus begitu saja karena masih menjadi referensi bagi riwayat akademik.

**Dampak jika master mata kuliah dihapus menggunakan CASCADE:**

Seluruh riwayat pengambilan mata kuliah dan transkrip nilai mahasiswa yang terkait dapat ikut terhapus secara permanen. Hal tersebut berisiko merusak catatan nilai, perhitungan IPK, dan integritas riwayat akademik. Karena itu, penghapusan mata kuliah yang masih direferensikan sebaiknya ditolak menggunakan `RESTRICT`.

## 5. Hasil Latihan dan Modifikasi

### A. Penambahan Constraint SKS Minimal

```sql
ALTER TABLE mata_kuliah
ADD CONSTRAINT ck_mk_sks_min
CHECK (sks_mk >= 1);
```

**Keterangan:**

Constraint `ck_mk_sks_min` memastikan nilai SKS minimal adalah 1. Jika nilai SKS yang dimasukkan kurang dari 1, data akan ditolak oleh sistem basis data yang mendukung penegakan constraint `CHECK`.

### B. Modifikasi Foreign Key Mahasiswa - Dosen PA

```sql
ALTER TABLE mahasiswa
DROP FOREIGN KEY fk_mhs_dosen_pa;

ALTER TABLE mahasiswa
ADD CONSTRAINT fk_mhs_dosen_pa
FOREIGN KEY (id_dosen_pa)
REFERENCES dosen (id_dosen)
ON DELETE SET NULL;
```

**Keterangan:**

Penggunaan `ON DELETE SET NULL` memungkinkan data mahasiswa tetap tersimpan ketika data dosen pembimbing akademik dihapus. Kolom `id_dosen_pa` pada mahasiswa terkait akan berubah menjadi `NULL` sampai dosen pengganti ditetapkan.

### C. Analisis Kepatuhan AB-02 dan UU PDP

Penggunaan `ON DELETE SET NULL` membantu menjaga data mahasiswa tetap tersedia ketika dosen pembimbing dihapus. Informasi dosen pembimbing dapat diperbarui ketika dosen pengganti ditetapkan.

Dari sisi perlindungan data pribadi, pengelolaan data harus memperhatikan prinsip pembatasan tujuan, akurasi, dan minimisasi data sesuai konteks penerapan UU Perlindungan Data Pribadi (UU PDP). Penggunaan `SET NULL` sendiri tidak otomatis menjamin kepatuhan terhadap UU PDP, tetapi dapat mendukung pengelolaan relasi data yang lebih tepat.

```sql
CHECK (sks_mk >= 1 AND sks_mk <= 6)
```

Sementara itu, aturan yang melibatkan beberapa baris, seperti batas maksimal total SKS dalam satu KRS, membutuhkan mekanisme tambahan seperti trigger atau prosedur validasi yang sesuai dengan rancangan basis data. Penerapannya dibahas pada Modul 14.7.

## 7. Pembahasan dan Kendala

### Kendala Teknis

Kesalahan terjadi ketika urutan eksekusi skrip tidak sesuai dengan hubungan antartabel. Tabel transaksi dibuat sebelum tabel referensi induknya tersedia.

**Solusi:**

- Menjalankan `DROP TABLE` dari tabel anak ke tabel induk.
- Membuat tabel master terlebih dahulu.
- Membuat tabel transaksi setelah seluruh tabel induk tersedia.
- Memastikan seluruh nama kolom dan tipe data foreign key sesuai dengan kolom yang direferensikan.

Urutan ini membantu mencegah kesalahan relasi foreign key saat proses pembuatan ulang struktur database.
