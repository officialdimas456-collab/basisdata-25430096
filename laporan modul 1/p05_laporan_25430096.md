## 2. Ringkasan Dasar Teori

*Data Definition Language* (DDL) adalah kumpulan perintah SQL yang digunakan untuk membuat, mengubah, dan menghapus struktur basis data, seperti basis data, tabel, indeks, dan relasi.

Dalam perancangan basis data relasional, *constraint* digunakan untuk menjaga integritas dan validitas data. Jenis-jenis constraint meliputi:

- `PRIMARY KEY`: Menjadi identitas unik setiap baris.
- `FOREIGN KEY`: Menjaga hubungan antar tabel.
- `UNIQUE`: Mencegah duplikasi nilai.
- `NOT NULL`: Mencegah kolom berisi nilai kosong.
- `CHECK`: Memastikan nilai memenuhi kondisi tertentu.

Selain itu, aturan referensial seperti `ON DELETE CASCADE` dan `ON DELETE SET NULL` menentukan tindakan sistem ketika data pada tabel induk dihapus.

### 3.1 Inisialisasi Database dan Tabel Induk

Database yang digunakan adalah `db_akademik_096`.

```sql
CREATE DATABASE IF NOT EXISTS db_akademik_096;
USE db_akademik_096;

DROP TABLE IF EXISTS detail_krs;
DROP TABLE IF EXISTS krs;
DROP TABLE IF EXISTS mahasiswa;
DROP TABLE IF EXISTS mata_kuliah;
DROP TABLE IF EXISTS dosen;

CREATE TABLE dosen (
    id_dosen SMALLINT NOT NULL AUTO_INCREMENT,
    kode_dosen CHAR(3) NOT NULL,
    nidn CHAR(10) NOT NULL,
    nama_dosen VARCHAR(100) NOT NULL,
    prodi_dosen VARCHAR(60) NOT NULL,
    PRIMARY KEY (id_dosen),
    UNIQUE KEY uq_dosen_kode (kode_dosen),
    UNIQUE KEY uq_dosen_nidn (nidn)
) ENGINE=InnoDB;

CREATE TABLE mata_kuliah (
    id_mk INT NOT NULL AUTO_INCREMENT,
    kode_mk VARCHAR(10) NOT NULL,
    nama_mk VARCHAR(100) NOT NULL,
    sks_mk INT NOT NULL DEFAULT 3,
    semester_penawaran TINYINT NOT NULL DEFAULT 1,
    PRIMARY KEY (id_mk),
    UNIQUE KEY uq_mk_kode (kode_mk),
    CONSTRAINT ck_mk_sks
        CHECK (sks_mk > 0 AND sks_mk <= 6)
) ENGINE=InnoDB;

CREATE TABLE mahasiswa (
    id_mahasiswa INT NOT NULL AUTO_INCREMENT,
    nim CHAR(8) NOT NULL,
    nama_mhs VARCHAR(100) NOT NULL,
    prodi_mhs VARCHAR(60) NOT NULL,
    no_hp_mhs VARCHAR(15) NULL,
    status_mhs ENUM('aktif', 'cuti', 'nonaktif')
        NOT NULL DEFAULT 'aktif',
    tgl_daftar_mhs DATE NOT NULL,
    id_dosen_pa SMALLINT NULL,
    PRIMARY KEY (id_mahasiswa),
    UNIQUE KEY uq_mhs_nim (nim),
    CONSTRAINT fk_mhs_dosen_pa
        FOREIGN KEY (id_dosen_pa)
        REFERENCES dosen (id_dosen)
        ON DELETE SET NULL
) ENGINE=InnoDB;
```

### 3.2 Pembuatan Tabel Transaksi dan Detail KRS

```sql
CREATE TABLE krs (
    id_krs INT NOT NULL AUTO_INCREMENT,
    no_krs CHAR(12) NOT NULL,
    tgl_pengisian DATETIME NOT NULL,
    semester_akademik CHAR(5) NOT NULL,
    id_mahasiswa INT NOT NULL,
    PRIMARY KEY (id_krs),
    UNIQUE KEY uq_krs_no (no_krs),
    CONSTRAINT fk_krs_mahasiswa
        FOREIGN KEY (id_mahasiswa)
        REFERENCES mahasiswa (id_mahasiswa)
) ENGINE=InnoDB;

CREATE TABLE detail_krs (
    id_krs INT NOT NULL,
    id_mk INT NOT NULL,
    nilai_huruf CHAR(2) NULL,
    nilai_angka DECIMAL(3,2) NULL,
    PRIMARY KEY (id_krs, id_mk),
    CONSTRAINT fk_detail_krs
        FOREIGN KEY (id_krs)
        REFERENCES krs (id_krs)
        ON DELETE CASCADE,
    CONSTRAINT fk_detail_mk
        FOREIGN KEY (id_mk)
        REFERENCES mata_kuliah (id_mk),
    CONSTRAINT ck_detail_nilai_angka
        CHECK (nilai_angka >= 0.00 AND nilai_angka <= 4.00)
) ENGINE=InnoDB;
```

## 4. Jawaban Titik Analisis

### Titik Analisis 1: Perbedaan CASCADE dan RESTRICT

**Pertanyaan:** Mengapa `fk_detail_krs` menggunakan `ON DELETE CASCADE`, sedangkan `fk_detail_mk` tidak? Apa yang terjadi pada riwayat akademis jika mata kuliah dihapus beserta seluruh detailnya?

**Jawaban:**

Tabel `detail_krs` merupakan rincian dari tabel `krs`. Oleh karena itu, ketika data KRS dihapus, seluruh detail yang terkait juga harus dihapus secara otomatis menggunakan `ON DELETE CASCADE`. Hal ini mencegah munculnya data yatim (*orphan data*).

Sebaliknya, tabel `mata_kuliah` merupakan tabel master yang menjadi referensi riwayat akademik mahasiswa. Penghapusan mata kuliah yang pernah diambil dapat merusak riwayat transkrip apabila seluruh detail KRS ikut terhapus. Karena itu, penghapusan mata kuliah yang masih direferensikan sebaiknya ditolak menggunakan aturan `RESTRICT` atau perilaku default penolakan penghapusan pada foreign key.

## 5. Hasil Latihan dan Modifikasi

### 5.1 Latihan 1: Menambahkan Constraint CHECK SKS Minimal

```sql
ALTER TABLE mata_kuliah
ADD CONSTRAINT ck_mk_sks_min
CHECK (sks_mk >= 1);
```

**Pengujian:**

Percobaan memasukkan data mata kuliah dengan SKS bernilai `0` ditolak oleh sistem karena tidak memenuhi constraint `ck_mk_sks_min`.

### 5.2 Latihan 2: Modifikasi Foreign Key Dosen PA

```sql
ALTER TABLE mahasiswa
DROP FOREIGN KEY fk_mhs_dosen_pa;

ALTER TABLE mahasiswa
ADD CONSTRAINT fk_mhs_dosen_pa
FOREIGN KEY (id_dosen_pa)
REFERENCES dosen (id_dosen)
ON DELETE SET NULL;
```

**Keterangan:**

Constraint `ON DELETE SET NULL` menjaga data mahasiswa tetap tersimpan ketika data dosen pembimbing akademik dihapus. Nilai kolom `id_dosen_pa` pada mahasiswa terkait akan berubah menjadi `NULL`.

## 7. Pembahasan dan Kendala

### 7.1 Kendala 1: Kesalahan Foreign Key saat DROP/CREATE

**Penyebab:**

Galat muncul karena tabel induk dihapus sebelum tabel anak yang masih memiliki relasi foreign key.

**Cara mengatasi:**

Penghapusan tabel dilakukan dari tabel anak ke tabel induk dengan urutan:

1. `detail_krs`
2. `krs`
3. `mahasiswa`
4. `mata_kuliah`
5. `dosen`

Urutan ini membantu menghindari konflik foreign key ketika tabel dihapus.

### 7.2 Kendala 2: Pelanggaran Constraint CHECK SKS

**Penyebab:**

Galat terjadi ketika data SKS yang dimasukkan berada di luar rentang yang diizinkan, yaitu 1 hingga 6.

**Cara mengatasi:**

Data masukan pada perintah `INSERT` disesuaikan agar memenuhi aturan bisnis akademik yang telah ditetapkan.
